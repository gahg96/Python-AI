## 1. 系统概述

**Lead-to-Cash (L2C)** 系统是一款专为现代企业设计的全流程资源规划（ERP）解决方案。它打通了从“线索发现”到“现金回笼”的完整业务闭环，消除了销售、交付、财务部门之间的各种信息孤岛。

### 核心价值
- **流程协同**: 销售签订合同后，系统自动触发项目立项，无需人工传递线下文档。
- **财务合规**: 所有的开票请求必须基于合同里程碑的验证状态，确保“先干活，后收钱”或“按约收款”。
- **风险可控**: 合同审批流程内置风险评估，项目执行过程中实时监控利润率（Margin）。

### 功能模块架构
1.  **机会管理 (Opportunities)**: 销售漏斗、跟进记录、报价管理。
2.  **合同管理 (Contracts)**: 合同起草、在线审批、电子签署、里程碑定义。
3.  **项目管理 (Projects)**: 任务分配、资源工时、成本核算、进度跟踪。
4.  **财务中心 (Finance)**: 发票开具、回单管理、收款核销、财务报表。
5.  **采购管理 (Procurement)**: 投标管理、采购任务分配。

## 2. 快速入门

### 2.1 登录系统
1.  打开浏览器访问系统地址（例如: `http://localhost:3000`）。
2.  在登录页面输入您的用户名和密码。
3.  点击“登录”按钮。
    *   *注意*: 如果您忘记密码，请联系系统管理员重置。

### 2.2 仪表盘 (Dashboard)
登录成功后，您将看到默认的仪表盘页面，这里汇聚了您最关心的核心指标：
-   **销售概览**: 本季度新增商机数量、预计签约金额。
-   **待办事项**: 等待您审批的合同、需要验证的里程碑。
-   **财务简报**: 本月待回款金额、已逾期发票预警。

### 2.3 导航栏说明
系统左侧（或顶部）为全局导航栏：
-   **Dashboard**: 回到主页。
-   **Opportunities**: 商机/销售线索管理。
-   **Contracts**: 合同管理。
-   **Projects**: 项目交付管理。
-   **Finance**: 财务与发票。
-   **Customers**: 客户信息库。
-   **Procurement**: 招投标与采购。

## 3. 商业机会管理 (CRM)

此模块主要由**销售代表**和**销售总监**使用。

### 3.1 创建新商机
1.  点击导航栏的 **Opportunities**。
2.  点击右上角的 **"New Opportunity"** (新建商机) 按钮。
3.  填写商机详情表单：
    *   **Title (标题)**: 简明扼要地描述商机（例如：“XX集团2026年数字化转型项目”）。
    *   **Customer (客户)**: 从下拉列表中选择现有客户。如果是新客户，请先去“客户管理”模块创建。
    *   **Estimated Value (预计金额)**: 预估的项目合同金额。
    *   **Win Probability (赢单率)**: 根据当前沟通情况填写（0-100%）。
    *   **Close Date (预计签约日期)**: 预计完成签单的时间。
4.  点击 **"Create"** 保存。

### 3.2 跟进与协作
进入商机详情页后，您可以看到多个标签页：
-   **Overview (概览)**: 修改基本信息，更新销售阶段（New -> Proposal -> Negotiation -> Won）。
-   **Follow Ups (跟进记录)**: 记录每一次客户拜访、电话会议的纪要。不仅可以作为个人备忘，也便于销售经理了解项目进展。
-   **Attachments (附件)**: 上传客户需求文档、RFP文件、技术方案PPT等。

### 3.3 商机关闭 (赢单/输单)
当项目确定成交或丢失时，必须更新状态：
-   **赢单 (Won)**: 点击状态栏的 "Won"。**注意**：只有状态变为 "Won" 后，系统才会允许基于此商机创建合同。
-   **输单 (Lost)**: 如果客户选择了竞争对手，请选择 "Lost"，并在备注中说明原因（价格、技术、关系等），以便后续分析。

## 4. 合同全生命周期管理 (CLM)

合同是连接销售与交付的桥梁。确保合同信息的准确性是后续开票和收款的前提。

### 4.1 起草合同
1.  **入口**: 在状态为 "Won" 的商机详情页右上角，点击 **"Create Contract"** 按钮。
2.  系统会自动带入商机名称、客户信息和预估金额。
3.  **完善信息**:
    *   **Contract Number (合同编号)**: 系统默认生成以 `CON-` 开头的唯一编号（例如 `CON-2026-0001`）。
    *   **Total Value (合同总额)**: 最终确认的签约金额。
    *   **Dates (日期)**: 设置合同生效日和结束日。

### 4.2 定义里程碑 (Milestones) - **关键步骤**
合同的收款条款通常是分阶段的。您必须在系统中清晰定义这些阶段，这直接决定了未来何时能开发票。
1.  在合同详情页，找到 **"Milestones"** 区域。
2.  点击 **"Add Milestone"**。
3.  填写里程碑信息：
    *   **Name**: 例如“首付款”、“蓝图确认”、“UAT验收”、“项目维保”。
    *   **Amount**: 该阶段应收金额。
    *   **Description**: 具体的验收标准。
4.  重复添加，直到所有里程碑金额之和等于合同总额。

### 4.3 风险评估
在提交审批前，请切换到 **"Risk Assessment"** 标签页，填写项目的潜在风险：
-   技术风险（如：采用了未验证的新技术）。
-   商务风险（如：付款账期过长）。
-   交付风险（如：工期紧张）。

### 4.4 审批与签署流程
1.  **提交审批**: 检查所有信息无误后，点击 **"Submit for Approval"**。合同状态变为 `Pending Approval`。
2.  **经理审批**: 审批人（Manager角色）登录系统，查看合同详情，点击 **"Approve"** (批准) 或 **"Reject"** (驳回)。
3.  **签署**: 合同被批准后，状态变为 `Approved`。销售代表与客户完成线下盖章后，点击系统中的 **"Sign Contract"** 按钮，并可上传扫描件作为存档。
    *   *系统动作*: 点击 "Sign Contract" 会自动锁定合同内容，并**自动创建关联的项目 (Project)**，状态初始化为 `Initialization`。

## 5. 项目交付与执行

此模块主要由**项目经理 (PM)** 和 **交付团队** 使用。

### 5.1 项目初始化
项目由合同签署自动触发创建，继承了合同的名称和基本信息。
1.  点击导航栏 **Projects**。
2.  在列表中找到新创建的项目（通常显示为 `Initialization` 状态）。

### 5.2 组建团队
1.  进入项目详情，切换到 **"Team"** 标签页。
2.  点击 **"Add Resource"**。
3.  选择员工（User），设定其在项目中的角色（Developer, Consultant, PM等）以及投入开始和结束时间。
4.  系统会根据员工的费率（Rate）自动计算预计的人力成本。

### 5.3 进度与风险管理
-   **Dashboard**: 查看项目的预算消耗情况（Budget vs Actual Cost）、实时利润率（Margin）。
-   **Risks**: 持续跟踪项目执行过程中的风险，可以新增或关闭风险项。

### 5.4 财务里程碑验证 (Billing & Verification)
这是连接交付与财务的最关键环节。
1.  切换到项目中新增的 **"Milestones & Billing"** (里程碑与计费) 标签页。
2.  这里列出了与合同一致的所有里程碑。
3.  **验证 (Verify)**: 当交付团队完成了某个阶段的工作（如客户已签署UAT验收单），PM必须找到对应的里程碑，点击 **"Verify"** 按钮。
    *   状态变化: `Pending` -> `Verified`。
4.  **通知财务**: 里程碑变为 `Verified` 状态后，系统界面上会出现 **"Generate Invoice"** (生成发票) 的按钮，提示可以进行开票操作。

## 6. 财务管理与开票

此模块主要由**财务专员**使用。

### 6.1 发票开具 (Invoicing)
系统支持两种开票模式，推荐使用“基于里程碑”的模式。

#### 模式A: 基于里程碑开票 (推荐)
1.  进入 **Finance** -> **Dashboard**，查看 "Ready to Invoice" 列表。
2.  或者直接在 **Project** 的详情页，点击已验证里程碑旁的 **"Generate Invoice"** 按钮。
3.  系统自动生成发票草稿，金额、客户信息自动带入，无需手工录入，避免错误。
4.  检查发票信息（税率 6% 或 13%），确认无误后保存。

#### 模式B: 手工开票
1.  进入 **Finance** -> **Invoices** -> **New Invoice**。
2.  手动选择客户、合同，输入金额。此方式主要用于非标准收款场景。

### 6.2 发票管理与回单
1.  **查看发票**: 在发票列表中点击发票号进入详情。
2.  **编辑备注**: 如果有特殊说明（如：“客户看这里：请汇款至新账号”），点击备注旁的“编辑”按钮进行更新。
3.  **上传电子回单 (Receipt Upload)**:
    *   当发票已开具并发送给客户（或上传至税局系统）后，可以将电子发票PDF或扫描件作为附件上传。
    *   在发票详情页下方，点击 **"点击上传电子回单"** 区域，选择文件上传。
    *   上传后支持下载查看。

### 6.3 记录收款 (Payment)
1.  当银行收到款项后，财务人员打开对应的发票详情页。
2.  点击 **"Record Payment"** (记录收款) 按钮。
3.  填写：
    *   **Amount**: 实收金额（支持分批收款）。
    *   **Date**: 实际到账日期。
    *   **Method**: 支付方式（银行转账、支票、现金等）。
4.  系统自动计算剩余待收金额。当实收金额 >= 发票金额时，发票状态自动更新为 `Paid` (已结清)。同时，关联的里程碑状态也会更新为 `Paid`。

## 7. 采购与招投标管理

用于管理售前阶段的投标工作。

1.  **创建投标 (New Tender)**: 在 **Procurement** 模块记录收到的招标文件（RFP/RFQ）。
2.  **任务拆解**: 将投标工作拆解为“技术标书撰写”、“商务报价测算”等任务，并指派给不同人员。
3.  **结果跟踪**: 记录最终投标结果（Win/Loss），为未来投标提供数据参考。

## 8. 客户与主数据管理

所有业务的基础。建议由专人（如销售运营）统一维护，确保数据质量。

-   **客户信息**: 公司名称、纳税人识别号、地址、联系人。
-   **数据唯一性**: 系统通过纳税人识别号进行查重，避免重复创建客户。

## 9. 常见问题解答 (FAQ)

**Q1: 为什么我无法创建合同？**
A: 请检查关联的商机状态。只有状态为 `Won` (赢单) 的商机才能创建合同。

**Q2: 项目里程碑无法验证，"Verify" 按钮是灰色的？**
A: 只有项目处于 `Execution` (执行中) 状态，且您拥有项目经理权限时，才能操作里程碑验证。

**Q3: 发票金额搞错了怎么办？**
A: 如果发票状态还是 `Draft`，可以直接编辑或删除。如果已经记录了收款，需要先删除收款记录，再作废（Cancel）发票，然后重新开具。

**Q4: 合同编号规则可以修改吗？**
A: 目前系统默认使用 `CON-YYYY-XXXX` 格式（如 `CON-2026-0005`）。如需特殊规则，请联系技术支持团队进行后台配置。

**Q5: 如何导出报表？**
A: 在各个列表页（如发票列表、合同列表）的右上角通常有 "Export" 按钮，支持导出为 Excel/CSV 格式。
